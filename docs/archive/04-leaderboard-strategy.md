# 2026 AIC 三模态目标检测打榜方案

更新日期：2026-08-15

## 1. 目标与结论

本方案只服务于排行榜成绩，不再以“复现论文”作为实验目标。

硬目标：

- 本地排行榜代理验证集达到 `mAP@50–95 >= 0.70`；
- 初赛排行榜目标达到 `mAP@50–95 >= 0.75`；
- 最终只提交一个模型，最多输出 100 个预测框；
- 所有训练数据仅来自赛事官方训练集，外部资源只使用规则明确允许的 ImageNet、COCO、Objects365 等公开预训练权重。

立即执行的路线判断：

- 终止当前 YOLOv5s + ICAFusion/M²D-LIF 主线；
- 不运行 E09，不继续为 M²D-LIF 调蒸馏权重；
- E01–E08 仅保留为失败消融和数据管线回归测试；
- 新主线从强单模态检测器开始，先证明检测底座能够达到 60～70 分，再接入红外和深度；
- 任何实验若没有达到本方案规定的阶段门槛，立即淘汰，不用完整 150 epoch 去“碰运气”。

## 2. 官方规则边界

根据赛事官方说明：

- 评测指标为 12 类宏平均的 101 点插值 `mAP@50–95`；
- IoU 阈值为 0.50、0.55、…、0.95，共 10 个；
- 每张测试图必须提交同名 TXT，无检测也必须提交空文件；
- 每张图最多保留 100 个预测框；
- 禁止调用在线服务；
- 禁止使用测试集训练或人工标注测试集；
- 禁止多个不同模型做简单投票或平均集成；
- 允许使用 ImageNet、COCO、Objects365 等公开预训练权重。

因此，本方案不使用模型集成，不默认使用多模型 WBF，也不在未向组委会确认前使用多尺度 TTA 平均。最终结果来自单模型单检查点。

官方规则：

- https://www.aicomp.cn/tracks/tracks-1/3700.html

## 3. 当前结果与失败原因

现有最佳结果：

| 实验 | mAP@50–95 |
|---|---:|
| E01 RGB YOLOv5s | 0.27127 |
| E02 RGB+IR ICAFusion | 0.27595 |
| E04 RGB+IR+Depth | 0.27296 |
| E07 IR-only | 0.05783 |
| E08 M²D-LIF | 0.26057 |

结论：

1. 当前 YOLOv5s 底座上限约 0.27，远低于 0.75，继续更换融合模块没有意义。
2. E07 IR 教师只有 0.05783，不满足 M²D 需要强单模态教师的前提。
3. E08 的蒸馏与照明损失在最佳轮次约占总训练损失一半，弱教师反而限制学生。
4. 深度直接加入对 E04 没有增益，说明当前 Depth 表示或融合方式不合格。
5. 数据只有 2,000 组，类别极不均衡；宏平均指标会让 25 个 tricycle 框与 5,499 个 person 框具有相同类别权重。

## 4. 最关键的新发现：验证集与排行榜分布不一致

当前验证集采用采集组完全隔离的划分，适合测跨场景泛化，但可能严重低估排行榜成绩。

按当前文件名分组规则统计：

- 训练集：1,099 个采集组；
- 测试集：583 个采集组；
- 训练/测试重叠：367 个采集组；
- 1,000 张测试图中有 739 张属于训练集中已出现的采集组；
- 2,000 张训练图中有 869 张属于这些重叠采集组。

也就是说，约 73.9% 的测试图与训练图具有相同采集组。榜上 0.75 与当前严格分组验证 0.27 不能直接比较。

这不授权使用测试集训练。正确做法是只用训练集建立两套验证协议：

### 4.1 Leaderboard Proxy：主要模型选择指标

建立分层随机帧验证集，使同一长序列可同时出现在训练和验证中，以近似排行榜中大量同场景测试帧的分布。

要求：

- 按 12 类多标签分层；
- 保证 boat、ball、uav、tricycle 在验证集中都有足够样本；
- 固定随机种子并保存 manifest；
- 该指标作为打榜模型的第一选择标准。

### 4.2 Strict Group Holdout：次要鲁棒性指标

保留当前采集组完全隔离验证集，用于检测模型是否只记住背景。

选择规则：

- 排行榜代理指标优先；
- Strict 指标不得出现灾难性下降；
- 若 Proxy 提升超过 10 分而 Strict 不变，这是场景匹配收益，可以接受；
- 若 Proxy 极高但 Strict 接近 0，需要检查分组规则、重复帧和数据泄漏。

### 4.3 最终训练

确定结构与超参数后，使用全部 2,000 组官方训练数据训练一个最终模型。测试数据只用于离线推理，不参与训练、伪标签或超参数反向选择。

## 5. Phase 0：先证明评测和数据管线没有错

在启动强模型完整训练前，必须完成以下审计。

### 5.1 官方指标逐项对齐

- 确认类别编号 0～11 完全一致；
- 确认 AP 是 12 类宏平均，而不是按目标数量加权；
- 确认每类每 IoU 阈值按全数据集置信度排序；
- 确认 101 点 precision envelope 插值；
- 确认相同 GT 只能匹配一次；
- 确认最多 100 框的截断发生在正确位置；
- 用人工构造的完美预测验证本地得分必须为 1.0；
- 用故意偏移的框验证 IoU 0.50～0.95 曲线变化正确。

### 5.2 坐标与图像审计

随机可视化至少 200 组：

- 原图标签；
- letterbox 后训练标签；
- 模型预测还原到原图后的框；
- RGB、IR、Depth 同一目标的空间对齐情况。

重点检查：

- 是否发生两次归一化；
- xywh 与 xyxy 是否混用；
- letterbox padding 是否在恢复坐标时重复扣除；
- 80 个越界标签应采用保留、裁剪还是丢弃；
- 149 组 640×360 JPG 与 1,851 组 1920×1080 PNG 是否使用了正确的 Depth 解码；
- Depth 的 8-bit JPG 与 16-bit PNG 不能使用同一归一化公式。

### 5.3 小数据过拟合测试

从训练集选择 20 张图，关闭强增强，训练到：

- 训练集 `mAP@50–95 >= 0.90`；
- 主要目标框肉眼位置正确；
- rare class 样本能被记住。

若强模型无法过拟合 20 张图，不得启动完整实验；优先修复标签、损失、数据读取或评测问题。

### 5.4 Phase 0 通过门槛

- 完美预测得分 1.0；
- 20 图过拟合达到 0.90；
- Proxy 与 Strict 两套 manifest 均生成且无文件缺失；
- 官方提交 ZIP 校验通过。

## 6. 强检测底座路线

### 6.1 第一主线：D-FINE-L / D-FINE-X

优先使用官方 D-FINE，而不是继续扩展当前自研 YOLOv5。

理由：

- D-FINE 直接优化细粒度框回归，更符合 `mAP@50–95` 对高 IoU 定位的要求；
- 官方 D-FINE-L COCO AP 为 54.0，D-FINE-X 为 55.8；
- 官方提供 Objects365 与 Objects365+COCO 权重；
- 比赛规则明确允许 Objects365/COCO 公开预训练权重；
- 官方仓库提供自定义数据训练配置。

选择顺序：

1. D-FINE-L，Objects365+COCO 权重，1280 输入；
2. D-FINE-X，Objects365+COCO 权重，显存允许时作为更强单模型；
3. D-FINE-M 仅用于快速验证管线，不作为最终目标。

官方仓库：

- https://github.com/Peterande/D-FINE

### 6.2 对照主线：RT-DETRv2-L

如果 D-FINE 的数据适配出现问题，使用官方 RT-DETRv2-L 做独立对照，不修改其损失和匹配器。

官方仓库：

- https://github.com/lyuwenyu/RT-DETR

### 6.3 RGB-T 现成框架候选：YOLOv11-RGBT

只有强 RGB 底座达标后，才评估 YOLOv11-RGBT。该仓库已实现多种 RGB-T 融合模式，并支持 YOLO 与 RT-DETR 系列，适合做多模态结构参考。

官方/作者仓库：

- https://github.com/wandahangFY/YOLOv11-RGBT

使用原则：

- 先在本数据上跑其原生 RGB-T 流程；
- 不把其融合模块移植回当前 YOLOv5；
- 如果原生框架不超过强 RGB 基线至少 0.5 个百分点，立即淘汰；
- Depth 必须作为后续增量，不得一开始同时修改三处结构。

## 7. 模态表示与融合顺序

### 7.1 RGB 主模态

RGB 始终使用完整强检测器和公开预训练权重。IR/Depth 只能作为残差增强，不能替换或大幅扰动 RGB 主特征。

### 7.2 Infrared

赛事说明指出 IR 是三通道重复灰度，本质无彩色语义。优先表示：

- 单通道热灰度；
- 使用训练集统计量做全局标准化；
- 可增加局部对比度增强，但不得破坏 RGB/IR 几何同步；
- 不再使用几乎恒定的 valid mask 作为第二通道。

### 7.3 Depth

对 16-bit PNG：

- 原始毫米值；
- 有效掩码；
- `log(depth)` 或 inverse-depth；
- 0、过小值作为无效区域，不参与统计；
- 训练集统一估计归一化参数。

对 8-bit JPG：

- 单独的数据分支与归一化统计；
- 不伪装成毫米深度；
- 增加 modality-type 标记只在确实有收益时保留。

### 7.4 融合实验顺序

每次只改一个变量：

1. RGB D-FINE-L；
2. RGB + IR 早期通道融合；
3. RGB 主干 + IR 零初始化残差适配器；
4. 在最佳 RGB-IR 上加入 Depth 零初始化残差适配器；
5. 多尺度 P2/P3/P4 融合；
6. 最后才考虑动态门控。

推荐结构：

- RGB 使用完整 D-FINE backbone；
- IR 和 Depth 使用轻量 stem/adapter；
- 在 P2、P3、P4 通过零初始化 gate 加到 RGB 特征；
- 初始模型严格等价于 RGB 模型；
- gate 学不到有效增益时可以自然保持接近 0，不会像当前对称双主干一样拖垮 RGB。

## 8. 小目标与类别不均衡策略

训练集 14,417 个框，分布极不均衡：

| 类别 | 框数量 |
|---|---:|
| person | 5,499 |
| animal | 3,061 |
| car | 1,571 |
| light | 1,455 |
| sign | 809 |
| bicycle | 666 |
| seat | 621 |
| garbage_can | 282 |
| uav | 204 |
| boat | 135 |
| ball | 89 |
| tricycle | 25 |

由于最终指标按类别宏平均，rare class 是打榜关键。

采取以下措施：

- 使用 Repeat-Factor Sampling 或温和的 class-aware sampling；
- 对包含 boat、ball、uav、tricycle 的图像提高采样概率，但设置上限，避免过拟合；
- 使用官方训练数据内部的同步 Copy-Paste，RGB/IR/Depth 和标签必须一起复制；
- rare class Copy-Paste 必须保持合理尺度、遮挡关系和深度值；
- 对 tiny boxes 统计尺寸分布，必要时使用 P2 检测层；
- 输入优先 1280，验证有效后再尝试 1536；
- 避免会删除小目标的激进随机裁剪；
- Mosaic 只在早期使用，最后 15～20 epoch 关闭；
- 单独记录 12 类 AP，不接受只看总体均值。

## 9. 推荐训练配方

D-FINE-L 第一轮正式配方：

- 预训练：Objects365+COCO；
- 输入：1280，保持长宽比；
- 优化器：沿用官方 AdamW 配方；
- epoch：先做 50 epoch 快速门槛实验，达标后扩展到 100～150；
- AMP：开启；
- EMA：使用官方默认；
- 几何增强：同步 scale、translate、horizontal flip；
- 颜色增强：只作用 RGB；
- IR 强度增强：只作用 IR；
- Depth dropout/洞模拟：只有 Depth 已证明有增益后再启用；
- 最后阶段关闭强增强，专注高 IoU 定位；
- 每轮记录 `AP50`、`AP75`、`AP50–95` 和每类 AP。

不允许为了“复现论文”修改官方 D-FINE 的匹配器、回归损失或 decoder。先跑通强原版，再做多模态。

## 10. 实验矩阵与硬淘汰线

| 优先级 | 实验 | 目的 | 继续条件 |
|---|---|---|---|
| P0 | 指标/坐标审计 + 20 图过拟合 | 排除实现错误 | 20 图 AP >= 0.90 |
| P1 | D-FINE-M RGB 10～20 epoch | 快速验证新管线 | 明显超过当前 0.27 |
| P2 | D-FINE-L RGB 1280 | 建立强底座 | Proxy AP >= 0.60 |
| P3 | D-FINE-X RGB 1280 | 提升单模型上限 | 比 L 提升 >= 0.005 |
| P4 | D-FINE-L/X RGB+IR | 验证红外增益 | 比 RGB 提升 >= 0.005 |
| P5 | 最佳 RGB+IR + Depth | 完成三模态 | 比 RGB+IR 提升 >= 0.003 |
| P6 | 1536 + P2 小目标层 | 提升高 IoU/小目标 | 总 AP 提升 >= 0.005 |
| P7 | rare-class sampling/Copy-Paste | 补宏平均短板 | rare-class 均值提升且总 AP 不降 |
| P8 | 全 2,000 图最终训练 | 生成单模型提交 | Proxy 目标 >= 0.70 |

停止规则：

- 10～20 epoch 后仍未超过旧基线的结构直接淘汰；
- 完整训练提升小于 0.003，不再追加同方向实验；
- RGB 未达到 0.60 前禁止做复杂三模态融合；
- RGB+IR 未超过 RGB 前禁止加入 Depth；
- 任何辅助模态使主干下降超过 0.005，立即回退；
- 不对失败结构连续微调超过两次。

## 11. 验证与最终模型选择

快速阶段：

- 固定一套 Proxy split；
- 固定一套 Strict split；
- 所有模型用同一评测代码和同一图像尺寸比较。

候选结构确认后：

- 使用 3 个训练集内部的分层随机 split 验证稳定性；
- 3 折只用于选择超参数，不做模型集成；
- 用 3 折最佳 epoch 的中位数确定最终全量训练轮数；
- 最终使用全部 2,000 张官方训练图训练一个模型；
- 最终提交单个 EMA/checkpoint。

模型排序规则：

1. Proxy `mAP@50–95`；
2. Proxy `AP75`；
3. 12 类最低 AP；
4. Strict `mAP@50–95`；
5. 推理速度仅作为同分项，不优先于精度。

## 12. 推理与提交策略

- 单模型、单检查点；
- 输出每张图置信度最高的 100 框；
- AP 评测阶段置信度阈值保持足够低，避免提前损失召回；
- 不使用跨模型 WBF/NMS；
- D-FINE 默认端到端推理，除非验证证明需要额外 class-aware NMS；
- 每个测试样本都生成 TXT；
- 检查类别、坐标、置信度均合法；
- ZIP 根目录直接包含 1,000 个 TXT；
- 提交前运行格式校验和样本数校验；
- 首次排行榜提交只验证本地 Proxy 与线上分数的相关性，不立即大规模扫参。

## 13. 算力预算

第一阶段最多允许：

- 1 次数据/指标审计；
- 1 次 D-FINE-M 快速实验；
- 2 次 D-FINE-L 正式实验；
- 1 次 D-FINE-X 实验；
- 2 次 RGB+IR 实验；
- 2 次 Depth/rare-class 实验；
- 1 次全量最终训练。

总计不超过 9 次正式 GPU 训练。超过预算前必须根据排行榜反馈重排优先级。

## 14. 立即执行清单

下一步按以下顺序执行：

1. 冻结 E01–E08，不删除但不再训练；
2. 重新核验 `derive_group_id`，确认 367 个训练/测试重叠组不是分组算法误判；
3. 生成 `proxy_train.jsonl`、`proxy_val.jsonl` 和保留现有 Strict split；
4. 完成 20 图过拟合与官方指标对齐；
5. clone 并固定官方 D-FINE commit；
6. 将官方训练数据转换为 D-FINE 需要的 COCO JSON，保留 ZIP 或建立只读缓存；
7. 使用 D-FINE-M 做 10～20 epoch 快速试验；
8. 达标后运行 D-FINE-L Objects365+COCO、1280 RGB；
9. RGB 达到 0.60 后接入 IR；
10. RGB+IR 确认增益后再加入 Depth；
11. 本地 Proxy 达到 0.70 后生成第一次正式排行榜提交；
12. 根据线上/本地相关性决定是否投入 D-FINE-X、1536 和 rare-class 优化。

## 15. 成功标准

本方案不是以“代码能跑”作为完成标准。

成功标准只有：

- 本地 Proxy 达到至少 0.70；
- 排行榜达到或接近已知 0.75 水平；
- 最终模型严格遵守赛事单模型、官方数据和离线推理要求；
- 每个新增模块都通过独立消融证明有增益；
- 无法带来分数的论文、模块和训练配方立即舍弃。
